# Dependency qualification

Dependency Health is qualified when the selected native package-manager result
is normalized into schema-conform canonical evidence. A failed native analysis
blocks the capability; unavailable optional data is explicit evidence, not a
healthy zero.

The bundled `tde.generation-1.default` policy version `1.1.0` evaluates the
canonical unknown- and outdated-dependency metrics. These are generic pipeline
decisions, not claims about vulnerabilities, licenses, duplicates, unused
dependencies, or dependency drift.

The G2-B platform baseline and the explicit ecosystem boundary are recorded in
[the DJConnect dependency-health inventory](docs/djconnect-dependency-health-inventory.md).
