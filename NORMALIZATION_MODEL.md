# Normalization model

Normalization converts adapter-native observations into the one canonical, versioned Technical Debt Model. It produces project-independent, language-independent, stable, machine-readable records while retaining source meaning and provenance.

Each normalized observation binds a repository and candidate identity, capability, adapter identity and version, native tool identity and version, metric or finding, timestamp, limitations, and schema version. Normalization never invents analyzer facts or hides mapping loss.

The canonical envelope extends [EVIDENCE_SCHEMA.md](EVIDENCE_SCHEMA.md): canonical observations are the only input to validation, qualification, evidence publication, and reporting. Unsupported mappings, incompatible versions, or incomplete provenance fail closed.
